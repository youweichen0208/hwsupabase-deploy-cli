# 首次云端测试指南

本指南用于首次将真实前端接入已有华为云 RDS Supabase，并验证选定托管路线。仓库已有的本地容器测试见 [环境验证记录](environment-validation.md)，不代表云端结果。

将本仓库推送到 GitHub 只发布 skill 和文档，不会自动创建云资源或发布客户应用。安装/更新 skill 后，在实际前端项目目录发起以下任务。示例中的 profile、区域、应用和地址均需替换成实际值；不必一次测试所有路线。

## 1. 准备测试输入

| 输入 | 需要确认的内容 |
| --- | --- |
| 前端项目 | 源码位置、实际应用/workspace、构建脚本和锁文件、目标源码提交 |
| 测试目标 | 测试环境名称、所选托管路线、已有或拟创建的资源、允许修改的范围 |
| 华为云认证 | 已配置 profile、目标账号及区域、对应服务的读写权限；不把凭证贴入任务描述 |
| Supabase | 已有应用标识、实际 HTTPS API、公开 Key 的配置位置、允许测试的功能和账号 |
| 访问入口 | 域名/证书和 DNS 管理权限，或明确选择的 ECS IP；记录 HTTP/HTTPS |
| 费用与恢复 | 现有资源优先、允许新建的具体资源与预算、旧版本或部署前状态、测试资源保留/清理约定 |

优先使用独立测试环境和测试数据。若只能使用现有生产资源，先明确维护窗口、共享服务影响与恢复点。账号、地区、实例或 Supabase 存在多个候选时，由实际绑定和用户选择消歧。

## 2. 认证与只读预检

先按 [README 的认证入口](../README.md#认证入口与工具分工) 复用已有认证；首次永久 AK/SK 使用固定版本 DevKit 一次终端初始化，已有多账号配置先核对迁移影响。无需单独安装 obsutil。内部 OBS 保留实际 Endpoint 与独立配置，不运行默认 DevKit 初始化；特殊认证不走永久凭证简化入口。然后调用：

```text
$huawei-supabase-frontend 检查当前项目的云端测试条件。使用我已配置的 profile <名称>，目标区域 <Region ID>，测试路线 <OBS/CDN、内部 OBS 自定义域名、ECS 宿主机 Nginx、ECS Docker 或指定外部平台>，复用已有 Supabase <应用标识>。先只读核实认证、权限、资源、构建环境、入口和费用，列出缺项，不购买、不安装、不发布。
```

分别记录“配置已完成 / 云 API 可用 / OBS 可用”；OBS 路线使用 `hcloud obs` 查询目标桶，不以缺少全局列桶权限判定认证失败。测试统一入口的已知限制见 [认证验证记录](auth-validation.md)。

成功标准：目标账号/区域明确，本次所需只读 API 成功，已有资源和权限已核实；仅保存本地配置成功不算云认证通过。401/403、网络错误与资源列表为空分别处理。Project ID 仅在对应 API 需要时解析。没有 Supabase 候选不自动购买数据库。

ECS 还要独立核实 SSH 主机身份、登录用户及安装所需权限；KooCLI 认证不能替代 SSH。已有外部平台且只需接入后端时，按实际发布渠道验证权限，不强制增加华为云认证。

## 3. 准备环境并发布候选

| 路线 | 进入发布前的条件 | 本轮应核实 |
| --- | --- | --- |
| OBS/CDN | 专用私有桶、CDN 回源权限、可用域名/证书、DNS 权限及适用备案条件 | 实际返回的 CDN CNAME、HTTPS 入口、路由/缓存和桶资源隔离 |
| 内部 OBS 自定义域名 | 明确选择、实际 Endpoint、专用前端桶、访问范围授权和独立配置 | 按 [内部 OBS 流程](../skills/huawei-supabase-frontend/references/obs-custom-domain.md) 快照、网站/权限配置、上传、绑定域名、DNS/适用证书与恢复；无 CDN 不刷新 CDN |
| ECS 宿主机 Nginx | ECS/EIP、SSH、应用目录/端口权限和 Nginx | 配置检查、目录权限、入口切换及旧资源保留 |
| ECS Docker | 上述 ECS 条件，以及可用 Engine/Compose 和固定镜像 | daemon 目标、候选回环端口、只读挂载、健康状态、日志和恢复点 |
| 外部平台 | 实际托管服务、账号/项目权限及原有发布渠道 | 平台构建版本、候选/稳定地址、路由与实际回退能力 |

没有域名的 OBS 路线先交付构建产物和上线缺项；不能以 OBS 默认地址报告网站上线。ECS 仅有 HTTP IP 时，只验证静态页面连通，不输入真实登录凭证；完整 Auth 验收需要可信 HTTPS。实际执行细节分别见 [OBS](../skills/huawei-supabase-frontend/references/obs-release.md)、[ECS](../skills/huawei-supabase-frontend/references/ecs-hosting.md)、[Docker](../skills/huawei-supabase-frontend/references/docker-hosting.md)、[其他平台](../skills/huawei-supabase-frontend/references/external-hosting.md)。

完成预检并确定允许操作的范围后，可使用：

```text
$huawei-supabase-frontend 按刚才核实的目标准备测试环境并发布候选版本。允许在 <指定目标> 安装缺少的构建/静态服务工具，复用 <指定资源>，使用 <已确认路线>。新增付费资源仅限 <明确清单；没有则填“不新增”>。按项目版本和锁文件构建，接入已选定 Supabase，保留恢复点并记录实际入口与检查结果。
```

只安装实际所需工具：OBS 不装运行时；ECS 默认在本地/已有 CI 构建；Docker 按明确选择启用。上传前检查产物中的秘密、MIME、资源路径和环境参数。构建变量改变后重新构建；预览参数不直接当作生产参数推广。

## 4. 用真实入口验收

从目标用户网络，通过正常 URL 和浏览器访问；忽略证书错误、修改 Host 或加随机参数成功不能替代正常访问结果。测试结果使用“通过 / 失败 / 未验证 / 不适用”，不适用需说明原因。

| 检查 | 通过条件 |
| --- | --- |
| 首页与 TLS | 返回目标版本页面，HTTPS 证书有效、无强制下载或混合内容；HTTP 调试单列 |
| 资源 | 实际 JS/CSS/图片及懒加载资源可访问，MIME 正确，无浏览器加载错误 |
| 路由 | 深层 URL 直接打开和刷新成功，登录回调含查询参数仍可用 |
| 负面路径 | 缺失资源、未知 API、非页面路径返回 4xx，不返回首页 |
| 缓存 | 普通 URL 能看到当前版本，可变入口不长期缓存，旧页面引用的资源仍在 |
| Supabase | 浏览器能访问真实 HTTPS API，适用 CORS、登录/退出及回调通过 |
| 数据隔离 | 获授权的账号 A/B 各自访问业务允许的数据，跨用户私有数据不可见；匿名规则符合设计 |
| 服务状态 | ECS 对应服务状态正常；Docker 的运行状态、健康状态和实际页面分别验证 |

隔离测试只使用获授权的测试账号与数据，不能为通过测试关闭 RLS。没有测试账号、写入授权或安全入口时，把受影响项记为未验证，不报告整体线上通过。完整标准以 [通用验收](../skills/huawei-supabase-frontend/references/deployment.md) 为准。

首页和实际 JS/CSS/图片必须 GET 检查最终状态、Content-Type、Content-Disposition 与正文；根路径 XML、错误页或附件判失败。HEAD 仅作辅助，不能证明无强制下载。可复制的 shell/PowerShell（`curl.exe`）命令见 [GET 留证示例](../skills/huawei-supabase-frontend/references/deployment.md#get-留证示例)。跟随跳转后记录最终 URL 与最终响应。HTTP 成功或缺少 attachment 不等于页面可用，必须浏览器验证。`--resolve` 成功但正常解析失败时仅报告诊断通过。旧 HEAD 记录保留历史，下一次部署/回退补做 GET 和浏览器检查。

## 5. 验证更新、回退与失败恢复

在第一版通过后，发布有可见差异的第二版，记录两个版本与入口响应；核实旧版打开的页面仍可加载旧资源。然后调用：

```text
$huawei-supabase-frontend 回退测试环境到 <第一版的已验证版本标识>，恢复归档产物或原 deployment，检查普通入口、深层路由、新旧静态资源与后端兼容性，记录实际服务版本和恢复结果。
```

回退使用原产物或镜像，不重新构建旧源码冒充恢复。首次发布没有旧成功版本时，测试的是恢复部署前状态。数据库变更独立处理。

需要故障演练时，限定为已授权的隔离候选：例如错误 Nginx 配置应在校验阶段失败，不影响当前站点；构建/上传失败不切换入口。生产共享服务不做破坏性故障注入。请求超时或 SSH 中断后先查询实际服务版本，再决定恢复，不盲目重复创建资源或发布。

## 6. 留证与收尾

沿用项目既有记录；默认环境与发布记录放在实际应用项目的 `.hwsupabase/frontend/<环境>/`，排除 Git。记录字段见 [通用记录](../skills/huawei-supabase-frontend/references/deployment.md)。可用以下脱敏格式整理测试摘要：

```text
测试时间与操作者：
源码提交 / 构建工具版本：
环境 / 托管路线 / 服务方式：
目标账号非秘密标识 / 区域：
稳定入口及协议 / 候选地址：
Supabase 应用标识：
当前服务版本 / 最近成功版本 / 回退目标：
检查项：通过、失败、未验证、不适用及理由
请求方法 / 最终 URL（脱敏）/ normal 或 resolve-diagnostic：
最终状态 / Content-Type / Content-Disposition / 脱敏正文摘要 / 浏览器结果：
错误阶段 / 脱敏请求 ID / 恢复结果：
仍保留的资源及计费项 / 允许的清理范围：
完成状态：skill、本地应用、环境、线上验收分别填写
```

记录不包含 AK/SK、安全令牌、私钥、数据库密码、Service Role Key、cookie 或用户数据；提交公共仓库前另行检查资源标识及日志是否适合公开。仓库 `.gitignore` 不能自动保护其他应用项目，应核实实际应用的忽略规则。

测试后仅按约定删除本次创建且无共享依赖的资源、临时回调和测试数据；保留仍被旧页面引用的资源及所需恢复点。ECS 停机不等于磁盘/EIP 停止计费，不把约 300 元/月预算目标视为账单硬上限。
