## 本地执行

- Nginx image ID：`sha256:583b7f2fce1cdb8da5ad5c39ebd3c33b98b87d493190e548bdee1fa8c619c311`

从 Docker 指引直接提取 Compose YAML，从 ECS 指引提取 Nginx server 示例，仅替换测试目录。临时最小 Node 项目包含无第三方依赖的锁文件，执行 `npm ci --ignore-scripts` 与项目生产构建脚本，生成两个版本的 HTML/JS；此测试不代表 React/Vue 或客户依赖已实测。

在 daemon 的 Linux 文件系统创建独立测试存储，通过其父目录 bind mount 提供只读站点；发布辅助容器在同一 Linux 文件系统中原子替换相对 current 链接。测试端口仅绑定 127.0.0.1。测试后仅删除本次 Compose 服务、网络及测试存储，原有容器仍在运行。

首次使用 macOS 文件共享目录执行宿主机符号链接替换时，入口变为 404，短暂轮询未恢复。改为目标部署所要求的 Linux 同文件系统操作后，切换与回退均立即可见。指引据此要求核实实际挂载、限时检查普通 URL 的版本；Mac/Windows 共享目录结果不能替代 ECS/Linux 验收。没有将该失败描述为已经修复的 Docker Desktop 问题。

## 文档场景推演

以下为人工按指引检查的行为分支，不是已经执行安装的自动化测试。

| 场景 | 指引要求的处理 |
| --- | --- |
| Node 缺失 | 区分检查/安装授权，识别系统架构，以用户级隔离方式准备匹配版本 |
| .nvmrc 与 engines/CI 冲突 | 列明来源和冲突，停止依赖安装，不覆盖任一声明 |
| 同一 workspace 多锁文件 | 查实际发布渠道，无法确定时说明候选；不同应用的锁文件分别处理 |
| 固定版本已停止维护 | 报告支持状态及升级方案，复现与升级分别验证 |
| 无构建步骤的静态目录 | 验证产物，不要求 Node 或 Docker |
| 仅检查环境 | 查询版本和缺项，不安装、不重启、不发布 |
| 已有 CI 或外部平台 | 对照项目约束与平台版本，保留原发布渠道 |
| 缺少权限/系统不受支持 | 报告具体缺项，不替换系统工具或套用其他发行版命令 |
| 旧记录无 service_mode | 核实实际进程、容器和配置再补字段，保持原发布方式 |
| 已有镜像内置产物 | 使用原不可变镜像发布/回退，另验证旧资源保留，不强套 current 挂载 |
| 共享 daemon/宿主机 Nginx | 识别影响范围，应用更新不连带重启共享服务 |
