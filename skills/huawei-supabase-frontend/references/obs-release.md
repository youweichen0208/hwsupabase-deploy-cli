# OBS 版本发布与回退

仅在 OBS/CDN 路线读取；先完成 [托管配置](hosting.md)，通用记录与验收见 [发布与验收](deployment.md)。

## 发布顺序

1. 重新查询目标环境，核对与记录一致；先完成生产构建、秘密检查及本地预览。为本次发布分配唯一版本，以内容哈希 URL 或 `/releases/<版本>/` 保持资源不可变；版本前缀需在构建配置中生成正确资源 URL。HTML 中引用的图片、字体、动态 import 和无哈希 public 文件均需纳入清单。
2. 单一环境串行发布；切换前再次核对远端入口摘要与发布前快照一致。发现其他发布变更立即停止并对账，不能覆盖另一发布者。保存上一个已验证版本的原始入口字节、响应元数据和配置；回退不重新构建旧源码。
3. 先上传全部不可变资源，检查上传清单、大小及校验和，再通过授权读取验证对象内容与 MIME。分段对象 ETag 不一定是 MD5，不能仅比较 ETag 当作内容校验。允许已存在且摘要相同的对象；同一版本键内容不同则停止。
4. 确认全部依赖可用后才更新公开入口文件；静态多页入口逐个更新并记录完成进度，不能声称多对象原子切换。需要路由配置更新时保存旧规则、等待新规则生效，并把恢复顺序写入本次计划。应用必须允许发布期间新旧页面共存。
5. 不可变资源长期缓存，例如 `public, max-age=31536000, immutable`；HTML 用 `no-cache` 或经过确认的短 TTL。CDN 入口及页面规则设置为重新验证或短缓存，不能让默认扩展名/目录规则覆盖入口策略。service worker、manifest、运行时配置等可变文件单独短缓存并纳入刷新；有 service worker 时验证其更新和回退行为。
6. 刷新 `/`、`/index.html`、实际页面缓存键及变更的可变文件。动态路由按实际缓存键采用范围适当的目录刷新或经核实的刷新方式，核对配额与费用；不能列几个示例 URL 就认为动态页面全已刷新。记录任务 ID，查询直到完成，再通过普通 URL（非仅 cache-busting 参数）验收。
7. 只有适用验收通过后，才将本次版本记为成功并更新当前/前一成功版本。刷新失败、部分节点旧页面或测试缺失均记录为待完成，保留上一成功版本。

默认使用 KooCLI 内置 OBS 操作，先按 [认证指引](authentication.md) 验证 OBS 身份和目标桶权限；已有独立 obsutil 发布环境继续复用。使用以下示例时，变量须来自已核实环境。以下演示**单个入口最后上传**，前提是全部资源已校验且快照已保存；不是整套一键部署：

```sh
hcloud obs cp "$FRONTEND_ENTRY_FILE" "obs://$FRONTEND_BUCKET/index.html" \
  -vmd5 -meta='Content-Type:text/html#Cache-Control:no-cache'
```

执行前运行 `hcloud obs help cp` 核对当前版本参数及凭证配置；仅上传清单内产物，不递归上传整个项目。命令按官方 [上传对象](https://support.huaweicloud.com/utiltg-obs/obs_11_0013.html) 编写，本次没有云端执行背书。CDN 刷新命令版本也须核对，例如官方目录列出 `hcloud CDN CreateRefreshTasks/v2`；先 `--help`，再按实际 schema 生成请求，不混用旧版字段。

## 失败恢复与回退

- 入口切换前失败：当前线上入口保持原状，保留本次未完成清单，修复后从校验恢复；不删除旧资源。
- 上传/入口修改请求超时：先读取远端字节摘要和元数据，确定已完成、未完成或未知，不能盲目重传覆盖并发版本。
- 入口已切换或多页部分切换后失败：在部署所含恢复授权内恢复发布前已验证版本的所有入口、元数据及本次改动的路由/缓存配置，刷新相同页面缓存范围，再验收。首次发布没有旧成功版本时报告失败及已暴露内容，按约定恢复发布前状态，不宣称已回退成功。
- 显式回退：核对指定版本曾验收通过、资源仍在且当前 Supabase 接口兼容，按归档恢复入口与必要配置，完成刷新及验收后记录回退事件。数据库迁移不随前端回退自动逆转；不兼容时说明阻碍并准备修复方案。
- CDN 刷新、配置生效或恢复也失败：保留最后已知状态和任务 ID，标记线上结果未确定；说明仍计费的资源、受影响入口和下一步。状态查询默认最多等 30 分钟，瞬时读取最多重试三次；再次运行先对账，不重复创建。

至少保留上一个成功版本；仍可能被旧页面、浏览器缓存或 service worker 引用的资源继续保留。垃圾清理必须另有保留期限和授权，不在每次发布中使用破坏性同步删除。复用资源不进入本次失败清理范围。
