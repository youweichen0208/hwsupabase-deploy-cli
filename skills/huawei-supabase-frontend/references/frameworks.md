# 前端构建与静态适配

先读取 package.json、锁文件、框架配置和实际路由，按下文确认静态边界与路由。需要构建时再按 [构建环境](build-environment.md) 确定产物来源或构建位置并检查该环境的工具链。需要新产物时，已有项目沿用包管理器、Node 版本约束和构建脚本，按锁文件安装依赖，运行项目已有的类型检查、必要测试及生产构建；仅上传已有合格产物时直接验证并复用。新项目未指定框架时用 React＋Vite＋TypeScript；Vue、普通 HTML/CSS/JS 及已能静态导出的项目同样适用。

## 静态边界

检查 SSR、server routes、API handlers、服务端会话、运行时秘密密钥、动态图片处理及定时任务。只有生产构建输出能独立作为静态文件提供服务才进入本 skill 的静态发布流程。已有静态导出流程可以复用；依赖服务端运行时则说明具体路由/功能及额外后端需求，继续可独立完成的部分，不静默删除功能、改写业务或把服务器代码上传为可运行服务。

注入前端产物的配置会进入浏览器，仅注入允许公开的参数；保留项目需要的其他安全公开变量，Supabase 使用 HTTPS URL 和公开 Key。扫描构建输出、source map 和静态复制目录，确保没有 Secret/Service Role Key、数据库密码、云凭证、`.env` 或私钥。报告文件位置而非秘密值；发现秘密先修复并重新构建，泄漏过的凭证需单独处置。

## 资源与路由

确定构建目录，不假定始终为 dist。带哈希资源或版本前缀使用不可变 URL；public 目录中无哈希但可变化的文件也要版本化或列入短缓存与刷新清单。保持路由 basename 与构建资源 base 相互独立，版本前缀不能误变成浏览器页面路径。

生成页面路由清单及资源命名空间，例如页面 `/`、`/login`、`/auth/callback`、`/projects/:id`，资源 `/assets/` 和 `/releases/`，API `/api/`。动态页面规则限定参数语法；不以“无扩展名”作为所有请求的页面判定。多页静态导出保留每个页面的 HTML 和路由映射，不套用单页统一入口。

本地用项目生产预览验证首页、真实 JS/CSS、深层路由和登录页面；开发服务器成功不等于静态托管可行。生产预览自带的宽泛 SPA fallback 不能作为 CDN 路由正确的证据。

等待 OBS/CDN 所需域名时保留构建产物、实际预览地址、构建命令和待上线条件；没有实际运行的预览不称为“本地已验证”。无应用代码的 skill 维护任务无需生成演示应用。
