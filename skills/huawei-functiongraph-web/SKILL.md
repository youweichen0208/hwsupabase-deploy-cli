# FunctionGraph Web 部署

交付可构建的应用、可复用的 KooCLI 部署参数和经过验证的访问入口。支持 Flask、Express、Django；React/Vue 静态构建产物可由 Express 托管。

## 工作流

1. **识别目标。** 阅读项目说明、依赖清单、锁文件和启动脚本。复用已有框架与入口；新项目按用户选择创建。先检查目标区域的官方函数模板，匹配且可用则复用；没有适用模板才使用框架标准脚手架。不要假定模板名称、ID 或当前可用性。
2. **准备应用。** 阅读 [框架适配](references/frameworks.md) 的公共部分及对应框架章节。识别启动模块、构建输出和依赖，生成独立部署目录及 bootstrap。仅创建项目的请求在本地验证后结束，不创建云资源。
3. **准备部署。** 部署、更新或回滚前阅读 [KooCLI 部署](references/deployment.md)。先按 [认证与只读预检](references/authentication.md) 复用有效认证，支持 SSO、ECS 委托及 AKSK；以认证上下文和区域为最小输入，自动识别 profile、优先按 [区域映射](references/regions.md) 将自然语言区域名称解析为 region ID，并优先使用 KooCLI 自动获取 project ID；查询可复用的函数、APIG 和网络资源，首次创建后自动记录资源 ID 和访问入口。仅在自动发现失败或存在无法判定的候选时询问，不要求用户预先提供整套配置。先产出实际请求参数和资源变更说明。复用会话中已有授权；新增付费资源、公开入口、数据库迁移等超出授权的操作，执行前单独确认。
   需要 APIG 入口时必须阅读 [APIG 复用与自动开通](references/apig.md)，执行现有实例筛选、按需购买、就绪等待、网络配置、发布和失败恢复。
4. **按需接入后端。** 仅当用户要求 Supabase 时阅读 [RDS Supabase](references/supabase.md)。默认连接已有应用，前端部署不隐含购买数据库。
5. **执行并验证。** 用 KooCLI 完成已授权操作，记录函数 URN、入口资源 ID 和版本。按部署指引检查主页、静态资源、深层路由及适用的接口。云端不可验证时明确说明原因，区分“本地构建完成”“资源已更新”和“线上验证通过”。

## 工具边界

- 云资源管理优先直接使用 hcloud 命令及官方 JSON 参数格式。依据本地 --help 和对应区域官方资料确认能力，避免自建 AK/SK 签名器、通用 API 客户端或另一套部署 CLI。
- KooCLI 缺少某项能力时，先查官方专用工具或 SDK；说明具体缺口后才补最小适配。工具未安装、权限不足不等于 API 不存在。
- 本地构建、依赖安装、文件打包使用项目已有工具。仅在反复使用或正确性需要时增加辅助脚本。
- 部署失败先查询远端状态，尤其是创建请求超时；权限、参数及配额错误修正前停止重试。瞬时读取错误最多重试三次；创建结果不明时不得盲目重复创建。
- 保留用户现有配置和资源。更新前读取当前配置，合并需要修改的字段，避免覆盖其他环境变量、网络和委托。

## 交付

报告框架、修改的文件、部署包位置、执行过的验证，以及实际部署后的区域、函数 URN、访问 URL、版本和回退方式。只报告真实存在的资源和执行结果。模板及 API 资料的入口见 [官方资料](references/sources.md)。
